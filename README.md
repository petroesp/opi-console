# OPi Console

Веб-консоль на ESP32-C3 для двух Orange Pi, управления питанием плат и WireGuard.

## Сборка и загрузка

Установите PlatformIO и выполните команды из каталога проекта:

```sh
pio test -e native
pio run -e esp32c3
pio run -e esp32c3 -t upload
pio run -e esp32c3 -t uploadfs
```

`uploadfs` загружает локальные файлы терминала из `data/` в LittleFS. Выполняйте её после изменений веб-ресурсов. Настройки пользователей, Wi-Fi, реле и WireGuard хранятся отдельно в NVS и при загрузке LittleFS не удаляются.

Первый вход: `admin` / `admin`; смените временный пароль при первом входе. Задайте собственные сетевые и AP-пароли в `src/config.h` до развёртывания.

## Устройство программы

Прошивка выполняется на ESP32-C3 под Arduino. `setup()` загружает сохранённые параметры и запускает периферию, а `loop()` циклически обслуживает UART, сеть, WireGuard, реле, кнопку и OLED. Основная логика сделана как короткие неблокирующие шаги, чтобы обмен данными с платами продолжался во время подключения Wi-Fi и работы интерфейса.

| Файл | Назначение |
|---|---|
| `src/main.cpp` | Инициализация устройства, UART/WebSocket, HTTP API, реле, OLED, Wi-Fi и WireGuard |
| `src/config.h` | GPIO, сетевые значения по умолчанию, ограничения буферов и таймеры |
| `src/web_ui.h` | Встроенные HTML/CSS/JS страницы входа, терминалов и админки |
| `src/ws_uart.h` | Безопасная обработка текстовых и фрагментированных WebSocket-пакетов UART |
| `src/uart_rx_buffer.h` | Ограниченный кольцевой буфер чтения UART с последовательными номерами |
| `src/wifi_profiles.h` | Типы и проверка сохраняемых Wi-Fi-профилей |
| `src/vpn_profiles.h`, `src/vpn_storage.h` | Формат NVS и операции с профилями WireGuard |
| `src/wg_routes.h`, `src/wireguard_psk.*` | Выбор маршрута AllowedIPs и работа WireGuard с PSK |
| `data/assets/` | Статические библиотеки терминала, загружаемые в LittleFS |
| `test/` | Нативные тесты, работающие без подключённой платы |

### Обмен с UART

Каждому аппаратному UART соответствует объект `Console`: устройство `HardwareSerial`, WebSocket-адрес `/ws/0` или `/ws/1`, ограниченная история строк и RX-буфер. `pump()` читает не более 1024 байт за один проход `loop()`, сохраняет принятые байты для HTTP-чтения, разбивает поток на строки для OLED и собирает данные для браузеров. WebSocket передаёт потоковые данные терминалу, а короткие HTTP-запросы `/api/uart/read` используются браузером для получения последовательных блоков и восстановления после пропуска данных.

Ввод браузера отправляется напрямую выбранному UART. Для `/ws/0` и `/ws/1` права проверяются отдельно при подключении и при каждой записи; роль `ro` получает только чтение. Веб-терминал — байтовый UART-мост, а не эмулятор PTY: размер терминального окна и сигналы управления потоком на стороне Linux автоматически не согласуются.

### Настройки и хранение

Настройки хранятся в пространстве NVS `gw`, независимо от LittleFS:

| Ключ | Содержимое |
|---|---|
| `users` | Учётные записи, роли, случайные соли и хеши паролей |
| `wifi_v1` | До пяти Wi-Fi-профилей |
| `uart0`, `uart1` | Скорость, биты, чётность и стоп-биты каждого UART |
| `termNames` | Два пользовательских имени терминала |
| `r0`, `r1` | Последнее заданное состояние реле |
| `wg_profiles` | До трёх профилей WireGuard и их маршруты |

Секреты Wi-Fi и WireGuard нужны устройству в исходном виде для подключения и поэтому хранятся в NVS; API админки не возвращает Wi-Fi-пароли и PresharedKey. Потеря или очистка NVS удалит настройки и создаст временную учётную запись по умолчанию.

## Wi-Fi

В **Админ → Wi-Fi** можно сохранить от одной до пяти сетей. Порядок в форме задаёт порядок подключения: прошивка пробует текущую сеть 12 секунд, затем переходит к следующей и циклически повторяет список. Если STA-подключение не установлено, запускается точка доступа для настройки.

Пароли не возвращаются браузеру. При сохранении существующей сети оставьте поле пароля пустым, чтобы сохранить прежний пароль; для открытой сети отметьте соответствующий флажок. Чтобы удалить сеть, очистите её SSID. После сохранения устройство перезапускается. Если список ещё не сохранён, прошивка переносит compile-time сеть из `src/config.h` в первый профиль.

## Вход, роли и HTTP API

После входа браузер получает случайный cookie `sid` с флагами `HttpOnly` и `SameSite=Strict`. Сессии хранятся в RAM и истекают через 8 часов; после перезапуска нужно войти повторно. После пяти неверных паролей вход с этого IP блокируется на 30 секунд. Первый пароль `admin` обязан быть заменён до доступа к обычным страницам API.

Роли:

| Роль | Возможности |
|---|---|
| `ro` | Просмотр состояния и чтение UART |
| `rw` | Всё из `ro`, отправка данных UART и управление реле |
| `admin` | Всё из `rw`, пользователи, сеть, параметры UART, имена терминалов и WireGuard |

Основные маршруты:

| Маршрут | Метод | Доступ | Назначение |
|---|---|---|---|
| `/api/login` | POST | без сессии | Вход; возвращает cookie сессии |
| `/api/logout` | POST | сессия | Завершение сессии и удаление cookie |
| `/api/me` | GET | сессия | Имя, роль, необходимость смены пароля |
| `/api/passwd` | POST | сессия | Смена пароля |
| `/api/status` | GET | `ro` | IP, режим Wi-Fi, VPN, число сессий, реле и имена терминалов |
| `/api/uart/read?idx=N&since=S` | GET | `ro` | Следующий блок принятых байтов в hex и новая позиция |
| `/api/uart/send` | POST | `rw` | Передача поля `data` в канал `idx` |
| `/api/uart` | GET/POST | `admin` | Получить или сохранить UART-параметры; сохранение перезагружает плату |
| `/api/terminals` | GET | `ro` | Прочитать два имени терминалов |
| `/api/terminals` | POST | `admin` | Сохранить `name0` и `name1` (1–24 байта UTF-8) |
| `/api/relay` | POST | `rw` | `idx=0/1`, `act=on/off/cycle` |
| `/api/users` | GET | `admin` | Список учётных записей без паролей |
| `/api/users/add`, `/api/users/set`, `/api/users/del` | POST | `admin` | Управление учётными записями |
| `/api/wifi/profiles` | GET/POST | `admin` | Просмотр/сохранение Wi-Fi-профилей |
| `/api/vpn` | GET/POST | `admin` | Состояние или загрузка профиля WireGuard |
| `/api/vpn/delete` | POST | `admin` | Остановка и удаление профиля |

`idx=0` — UART Pi #1, `idx=1` — UART Pi #2. Вложенные маршруты `/api/uart/read` и `/api/uart/send` должны обрабатываться раньше базового `/api/uart`: HTTP-сервер сопоставляет базовый путь также с вложенными адресами.

## WireGuard

В админке доступны три отдельных wg-quick профиля; каждый может содержать свой `[Interface]`, один `[Peer]` и `PresharedKey`. PSK хранится в NVS и передаётся WireGuard-интерфейсу; API сообщает только о наличии ключа, но никогда не возвращает его значение.

Туннели подключаются независимо. Для IPv4-пакетов выбирается наиболее специфичный маршрут из `AllowedIPs`; если совпадающих маршрутов нет, пакет идёт обычным сетевым маршрутом Wi-Fi. Поддерживается до восьми IPv4-подсетей на туннель. Одинаковая подсеть не может быть назначена двум туннелям; при пересечении разных подсетей выигрывает более специфичный маршрут. Удаление останавливает только выбранный туннель и удаляет его профиль. Старый одиночный конфиг автоматически переносится в профиль №1.

После 8 секунд без активности UART OLED запускает самоходную змейку: она ищет еду по кратчайшему безопасному пути, растёт, а если пути к еде нет — выбирает свободное пространство. После столкновения игра начинается заново. При приёме или отправке данных OLED автоматически показывает активный терминал на 8 секунд; BOOT закрывает заставку и возвращает ручное переключение экранов.

Имена обоих терминалов можно менять в админке. Они сохраняются в NVS и показываются во вкладках веб-консоли и на OLED.

Змейка занимает сетку 32×8. Поиск еды использует BFS по клеткам; тело считается препятствием, за исключением хвоста, который сдвинется при обычном ходе. Когда прямой путь к еде не найден, выбирается допустимый ход с наибольшей доступной областью. Если допустимых ходов не осталось, игра автоматически начинает новый раунд.

Режимы дисплея: экран состояния, терминал 1, терминал 2 и сведения о сети/VPN. Короткое нажатие BOOT циклически меняет выбранный экран. Длинное нажатие открывает управление реле: коротким нажатием выбирается R1 или R2, долгим — подтверждается переключение. Активность UART временно имеет приоритет над выбранным экраном и заставкой.

## UART

| Канал | ESP32-C3 RX | ESP32-C3 TX |
|---|---:|---:|
| Pi #1 | GPIO0 | GPIO1 |
| Pi #2 | GPIO3 | GPIO4 |

Для каждого канала UART в **Админ → UART** можно независимо задать скорость (300–2000000 бод), биты данных (5–8), чётность (нет/чётная/нечётная) и стоп-биты (1/2). Исходные параметры — 115200 8N1, включая канал P2 к Linux. После сохранения ESP32 перезапускается; при загрузке данные по UART не передаются. Для Linux настройте соответствующий tty на те же параметры и отключите аппаратное/программное управление потоком. Подключение перекрёстное: ESP32 GPIO3 RX ← Linux TX, ESP32 GPIO4 TX → Linux RX, и соедините GND устройств. Уровни сигналов — 3,3 В. Для ручной проверки петли замкните **TX с RX одного и того же UART**. Соединение RX–RX не проверяет передачу. Не подключайте к GPIO сигналы RS-232 с уровнями ±12 В.

Кнопка BOOT: короткое нажатие переключает OLED-экраны. Долгое нажатие открывает управление реле: коротким нажатием выберите R1 или R2, долгим подтвердите переключение выбранного реле.

## Реле и перезапуск ESP32

| Плата | GPIO | Сохранённое состояние |
|---|---:|---|
| Pi #1 | GPIO7 | `r0` |
| Pi #2 | GPIO10 | `r1` |

Реле активны высоким уровнем (`RELAY_ACTIVE_HIGH=1`). Прошивка инициализирует их сразу после открытия NVS, до задержки запуска USB Serial, и восстанавливает сохранённое состояние. Это сокращает программный промежуток, когда выход ещё не настроен.

Во время аппаратного reset GPIO временно находится под управлением загрузчика/в высокоомном состоянии. Программно удерживать реле в этом интервале нельзя. Для активного высокого входа внешняя подтяжка GPIO к 3,3 В задаёт включённое реле на время reset; для безопасного выключенного состояния нужна подтяжка вниз. Простая фиксированная подтяжка не может сохранить произвольное последнее состояние реле: если требуется сохранять и включённое, и выключенное состояние без импульса, используйте аппаратную схему удержания/защёлку либо реле с подходящим входом. Учитывайте, что выбранная подтяжкой позиция действует во время reset, независимо от значения в NVS. Подключайте подтяжку только к логическому входу релейного модуля; GPIO не питает катушку.

## Тесты

`pio test -e native` проверяет UART-передачу и RX-буфер, ограничения и переход между Wi-Fi-профилями, а также удаление WireGuard-настроек при ошибках хранилища. После изменений прошивки дополнительно соберите `esp32c3` и проверьте на устройстве веб-админку, подключение к резервным сетям и восстановление состояния реле после перезапуска.

## Диагностика

- **Нет UART-вывода:** проверьте перекрёстное соединение TX/RX, общий GND и совпадение скорости/формата кадра на обеих сторонах. Для Linux отключите RTS/CTS и XON/XOFF, если они не используются.
- **На OLED не появляется терминал:** экран показывает терминал только при активности порта; после 8 секунд без передачи возвращается заставка/экран состояния. Убедитесь, что данные действительно приходят на RX ESP32.
- **Веб-терминал не принимает клавиши:** проверьте вход под ролью `rw` или `admin`; `ro` предназначена только для чтения.
- **Не удаётся открыть админку после обновления HTML:** загрузите LittleFS-компоненты командой `pio run -e esp32c3 -t uploadfs`, затем перезагрузите страницу браузера.
- **Состояние реле меняется при reset:** загрузчик временно управляет GPIO; программный код не может удерживать вывод до запуска `setup()`. Используйте подходящую внешнюю схему подтяжки на логическом входе релейного модуля.
